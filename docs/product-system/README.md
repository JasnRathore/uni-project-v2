# Product and system documentation

This documentation describes the product and the implementation evidenced in
the repository. It is intended for product, design, and engineering handoff;
it is not a substitute for runtime configuration or source-level verification.

## Start here

- [Product design](product-design.md) — audiences, capabilities, routes, user
  journeys, permissions, product constraints, and observable UX gaps.
- [System architecture](system-architecture.md) — system boundaries, stack,
  runtime/data flows, persistence, integrations, security boundaries,
  configuration, and operational limitations.
- [Implementation reference index](reference/README.md) — detailed source-file
  references, inventories, and coverage notes for controllers, components,
  services, data access, routes, and runtime modules.

The detailed reference is split into focused Markdown pages so an individual
controller, component, or system module can be read without navigating one
large document. Claims are grounded in repository files; inferred or unknown
behavior is labeled in the relevant page.
